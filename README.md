# make-knowledge-cards

一个面向 Claude Code 等支持 Agent Skills 工具的纯指令 Skill：把用户粘贴的文章或本地 Markdown/TXT 文件提炼成忠于原文、方便复习的知识卡片，并按需追加 Markdown 思维导图或自测题。

## 1. 项目解决什么问题

阅读长文章后，知识点往往散落在不同段落里，直接复习效率低；普通摘要又容易过度压缩，甚至加入原文没有的信息。手工把文章拆成单点卡片也费时，数量和质量都不稳定。

本 Skill 通过固定流程解决这些问题：

- 以原文为唯一知识来源，不补充外部知识，也不为凑数编造内容；
- 自动拆分和去重，让每张卡片只承载一个可独立复习的知识点；
- 控制卡片数量，原文知识点不足时如实减少；
- 默认只输出卡片，避免不必要的思维导图和题目干扰；
- 需要时再按需追加思维导图或自测题。

它适合整理学习笔记、备考材料、讲义和长文内容，不是网页抓取、PDF 解析或通用摘要工具。

## 2. 主要功能

- **读取文章**：支持直接粘贴文本，或读取用户指定路径的 `.md`、`.markdown`、`.txt` 文件。一次处理一篇。
- **生成知识卡片**：默认 5～8 张；原文独立知识点不足 5 个时输出实际数量，最多 8 张。用户明确指定数量时，在不超出原文知识点数量和 8 张上限的前提下遵循。
- **固定卡片结构**：每张卡片严格包含 `核心知识`、`简明解释`、`例子或自测问题` 三个字段，不添加其他字段。
- **忠于原文**：只提取原文明确表达的知识，保留关键条件与限定；卡片之间不重复，不为凑数拆分。
- **可选思维导图**：仅在用户明确要求时，追加基于卡片知识点整理的 Markdown 嵌套列表，不生成图片或 Mermaid 图。
- **可选自测题**：仅在用户明确要求时，追加配套题目和参考答案。默认每个知识点一道题，可混合判断题、选择题和简答题；如果明确表示不要答案，则省略参考答案。
- **输入不足提示**：输入为空、只有标题或不足以提炼出一个明确知识点时，只返回：
  ```text
  输入内容不足以提取知识点
  ```
- **输出语言**：跟随用户的明确要求或提问语言；三个卡片字段名始终保持中文。

两个可选模块默认关闭，只做追加，不替代知识卡片。同时开启时，顺序固定为：知识卡片 → 思维导图 → 自测题。

## 3. 安装方法

本 Skill 没有脚本、外部服务和额外 Python 依赖。将整个 `skills/make-knowledge-cards` 目录复制到目标工具的 Skills 目录即可。

### 安装到当前项目（推荐用于本仓库测试）

在仓库根目录执行：

```bash
mkdir -p .claude/skills
cp -r skills/make-knowledge-cards .claude/skills/
```

安装后的结构：

```text
.claude/skills/make-knowledge-cards/
├── SKILL.md
└── agents/
    └── openai.yaml
```

### 安装为个人级 Skill

如果希望所有项目都能使用，可改为复制到个人目录：

```bash
mkdir -p ~/.claude/skills
cp -r skills/make-knowledge-cards ~/.claude/skills/
```

项目级和个人级安装二选一即可。安装后重新打开 Claude Code；项目级安装需要从本仓库目录启动。客户端支持斜杠命令时，可以输入 `/make-knowledge-cards`，也可以直接用自然语言说明使用该 Skill。

其他支持 `SKILL.md` / Agent Skills 规范的工具，请按对应工具的 Skills 目录约定安装。`agents/openai.yaml` 是该类工具读取展示信息时使用的元数据，不参与知识提取。

## 4. 使用方法

### 准备输入

- **粘贴文章**：直接在请求中附上正文。
- **使用本地文件**：把文章保存为 `.md`、`.markdown` 或 `.txt`，在请求中给出路径。
- 一次只指定一篇文章或一个文件；不支持网页抓取、PDF/Word 解析。

### 默认用法：只生成知识卡片

```text
使用 make-knowledge-cards 处理下面文章，只输出知识卡片：

<粘贴文章正文>
```

读取本地文件：

```text
使用 make-knowledge-cards，读取 ./notes/article.md，生成知识卡片。
```

### 开启思维导图

在请求中明确加入“思维导图”或“脑图”：

```text
使用 make-knowledge-cards 处理下面文章，并附加 Markdown 思维导图：

<粘贴文章正文>
```

### 开启自测题

在请求中明确加入“自测”“出题”或“练习题”：

```text
使用 make-knowledge-cards 处理下面文章，并生成配套自测题：

<粘贴文章正文>
```

默认围绕每个知识点生成一道题，并在末尾给出参考答案。明确说“不要答案”时只输出题目。

### 同时开启两个模块

```text
使用 make-knowledge-cards 处理下面文章，并附加思维导图和自测题：

<粘贴文章正文>
```

输出顺序为：知识卡片 → 思维导图 → 自测题。

> 没有明确要求某个模块时，Skill 不会自动生成它。可选模块是追加内容，不会替代知识卡片。

## 5. 输入输出示例

### 输入

```text
北宋庆历年间，毕昇发明了活字印刷术。他用胶泥刻字，每字一印，经火烧硬后成为可以重复使用的字模。排版时，他把字模按韵排列，方便查找。
```

### 默认输出

```markdown
# 知识卡片

## 毕昇在北宋庆历年间发明活字印刷术
**核心知识**：北宋庆历年间，毕昇发明了活字印刷术。
**简明解释**：这项印刷技术的发明者是毕昇，发明时间是北宋庆历年间。
**例子或自测问题**：活字印刷术由谁在哪个时期发明？

## 胶泥字模经火烧硬后可以重复使用
**核心知识**：毕昇用胶泥刻字，每字一印，经火烧硬后制成可重复使用的字模。
**简明解释**：每个字单独用胶泥刻制并烧硬，成为排版时可以反复取用的字模。
**例子或自测问题**：毕昇的字模用什么材料制作，经过什么处理后可以重复使用？

## 活字按韵排列便于查找
**核心知识**：排版时把字模按韵排列，能够方便查找。
**简明解释**：字模依照韵部排列，取字时更容易找到所需的字。
**例子或自测问题**：毕昇采用什么方式排列字模？
```

原文只有 3 个独立知识点，因此输出 3 张卡片，没有为了达到 5 张而补写内容。

### 同时开启可选模块时的追加输出

用户请求：

```text
使用 make-knowledge-cards 处理这段材料，并附加思维导图和自测题。
```

在上述卡片之后，会继续追加：

```markdown
# 思维导图
- 毕昇与活字印刷术
  - 发明信息
    - 北宋庆历年间
    - 发明者毕昇
  - 字模制作与复用
    - 胶泥刻字，每字一印
    - 火烧硬后可重复使用
  - 排版方式
    - 按韵排列
    - 方便查找

# 自测题

1. （判断题）毕昇在北宋庆历年间发明了活字印刷术。
2. （简答题）毕昇用什么材料制作字模？字模经什么处理后可以重复使用？
3. （简答题）毕昇排版时如何排列字模？这样做的目的是什么？

## 参考答案

1. 正确。原文明确说明毕昇在北宋庆历年间发明了活字印刷术。
2. 用胶泥刻字，经火烧硬后可以重复使用。
3. 按韵排列，目的是方便查找。
```

## 能力边界

当前版本不支持：

- 网页抓取；
- PDF 或 Word 解析；
- Anki 导出；
- 图形界面。

遇到这些请求时，请先粘贴正文，或把内容转换为 `.md` / `.txt` 文件。一次只处理一篇文章或一个文件。

## 开发与校验

本项目只包含 Skill 指令和元数据，没有运行脚本。结构校验可使用官方 `skill-creator` 提供的 `quick_validate.py`（该脚本不随本仓库分发）：

```bash
python /path/to/skill-creator/scripts/quick_validate.py skills/make-knowledge-cards
```
